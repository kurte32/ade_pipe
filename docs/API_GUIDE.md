# API guide · Pipeline de Posibles Tiendas

Date: 11 October 2026 · Branch `ux-redesign` · **Audience:** frontend and integration developers, support reproducing a call · **When to read:** before calling or changing an endpoint · **Source of truth:** `docs/openapi.json` for shapes, `backend/app` for behaviour.

Practical reference for anyone calling the API: the two SPAs, support staff reproducing a problem
with `curl`, and future integrations. The machine-readable contract is `docs/openapi.json`
(regenerate with `make openapi`, then `pnpm gen:api` for the TypeScript client). This guide covers
what OpenAPI does not say: authentication, headers, errors, concurrency, pagination, the delta
sync and the upload protocol. Line references point into `backend/app`.

## 1. Base rules

- Prefix `/api/v1`. All paths are relative; the SPAs call their own origin and Front Door (or the
  Vite proxy locally) routes `/api/*` to the service.
- JSON in and out, except the bulk-load upload (`multipart/form-data`), the upload parts (raw
  bytes) and the file download (byte stream).
- Every request except `/healthz` and `/readyz` needs `Authorization: Bearer <token>` and one of
  the two application roles. A valid token with no role gets 403 everywhere.
- `/api/docs` and `/api/openapi.json` are served locally and in `test`, never in `production`.

## 2. Authentication and roles

Tokens are Entra ID v2 access tokens for the API registration (locally, RS256 tokens from
`tools/dev-idp` with the same claims). The service validates (`core/security.py`):

| Check | Rule |
|---|---|
| Signature | RS256 against the JWKS URL (cached one hour); the JWKS host must be `login.microsoftonline.com` in production |
| `iss`, `aud`, `tid` | Must equal `AUTH_ISSUER`, `AUTH_AUDIENCE`, `AUTH_TENANT_ID` |
| `scp` | Must contain `access_as_user`; app-only tokens are rejected |
| `azp` | Must be in `AUTH_ALLOWED_AZP` (the two SPA client ids); required non-empty in production |
| `oid` | Must be a UUID; it is the only source of the caller's identity |
| `roles` | Only `Admin` and `Coordinador` are kept; anything else is dropped |

Role by route family:

| Family | Coordinador | Admin |
|---|---|---|
| `/me`, `/sitios` (read), `/sitios/{id}/historial`, `/catalogos`, `/archivos/{id}` (read) | yes | yes |
| `/sitios/{id}/contacto`, `/visita`, `/transiciones`, `/subidas/*`, `DELETE /archivos/{id}`, `/notificaciones/*` | yes | no (403) |
| `/admin/*` | no (403) | yes |

Coordinators only ever see their own sites: the database applies row-level security from the
session context the API sets per connection (`SESSION_CONTEXT('oid')`, `('rol')`). A site that
belongs to someone else is a 404, not a 403.

Local tokens for `curl`:

```bash
TOKEN=$(curl -s http://localhost:8001/token -H 'content-type: application/json' \
  -d '{"user_code":"ard","client_id":"33333333-3333-4333-8333-333333333333"}' | jq -r .access_token)
curl -s http://localhost:8000/api/v1/me -H "authorization: Bearer $TOKEN"
```

Use client id `44444444-4444-4444-8444-444444444444` with user `adm` for admin calls.

## 3. Headers

| Header | Direction | Meaning |
|---|---|---|
| `ETag` | response | Site version (`rowversion` as `"<hex>"`) on `GET /sitios/{id}` and on every write that returns a site. On file downloads it is the file's SHA-256. |
| `If-Match` | request | Required on `POST /sitios/{id}/transiciones` and the three `/admin/sitios/{id}/*` actions. Missing: 428. Stale: 412 with the current site in `current`. |
| `Idempotency-Key` | request | Optional on `PUT …/contacto`, `PUT …/visita`, `POST …/transiciones`, `POST /subidas`. At most 80 characters. Same key and same body: the stored response is replayed (same status). Same key, different body or route: 422. Key still in flight: 409. Keys are per user and purged after `IDEMPOTENCY_TTL_DAYS` (7). |
| `X-Correlation-Id` | response | Always generated by the server (`uuid4` hex) and written to the audit ledger and to every error body. A value sent by the client is only logged as `client_correlation_id`. |
| `Range` | request | Single byte range on `GET /archivos/{id}`; 206 with `Content-Range`, 416 when unsatisfiable. |
| `Content-Length` | request | Checked before reading on upload parts and bulk loads; bodies over `MAX_REQUEST_BYTES` (12 MiB) get 413 without a correlation id (the limit runs before the correlation middleware). |

## 4. Errors (RFC 9457 Problem Details)

Every error is `application/problem+json` (illustrative body; titles come from the service that raises the error):

```json
{
  "type": "https://pipeline.tiendas3b/problems/precondition-failed",
  "title": "El sitio cambió",
  "status": 412,
  "detail": "…",
  "instance": "/api/v1/sitios/42/transiciones",
  "correlation_id": "f59800291da44734877fb96656d01088",
  "current": { "...SitioDetail..." }
}
```

| `type` slug | Status | When | Extra members |
|---|---|---|---|
| `unauthorized` | 401 | Missing or invalid token (signature, issuer, audience, tenant, scope, `azp`, `oid`) | |
| `forbidden` | 403 | Role not allowed on the route | |
| `not-found` | 404 | Missing or RLS-hidden site, lote, upload session, file, notification | |
| `conflict` | 409 | Idempotency key in flight; lote not in preview, already confirmed or cancelled | |
| `gone` | 410 | Download of a purged file | |
| `precondition-failed` | 412 | `If-Match` does not match the current `rowversion` | `current` (fresh `SitioDetail`) |
| `payload-too-large` | 413 | Body over the limit | |
| `range-not-satisfiable` | 416 | Bad `Range` | `Content-Range: bytes */size` header |
| `validation` | 422 | Schema errors (Pydantic) | `errors[]` with `loc`, `msg`, `type` |
| `unprocessable` | 422 | Business rule failed | `faltantes`, `estatus_actual`, `estatus_siguiente`, `missing`, `filas_pendientes`, `partes_faltantes`, `num_fila`, `errors` depending on the rule |
| `precondition-required` | 428 | `If-Match` missing where required | |
| `http-error` | other | Any other HTTP error, for example `/readyz` 503 with the per-check detail | |
| `internal` | 500 | Unhandled exception; never carries exception text | |

The SPAs map these in `packages/api-client/src/problem.ts` (`ApiError.slug`,
`isPreconditionFailed`, `isUnauthorized`, `current`).

## 5. Pagination

List endpoints return `{ items, next_cursor }`. Pass `cursor` back unchanged; cursors are opaque.

| Endpoint | `limit` | Order |
|---|---|---|
| `GET /sitios` | 1 to 200 | by id |
| `GET /admin/auditoria` | 1 to 200 (default 50) | newest first |
| `GET /admin/cargas/{id}` rows | 1 to 500 (default 100) | by row number; `resultado` filter `ok` / `advertencia` / `error` |
| `GET /admin/cargas` | 1 to 200 (default 50) | newest first, no cursor |

## 6. Site workflow calls

```text
GET  /sitios/{id}                       -> SitioDetail + ETag
PUT  /sitios/{id}/contacto              {nombre, telefono, correo?, notas?}      (Idempotency-Key)
PUT  /sitios/{id}/visita                {frente_m, fondo_m, area_m2?, fecha_visita_utc, notas?}
POST /sitios/{id}/transiciones          {estatus_destino, comentario?}            (If-Match, Idempotency-Key)
POST /admin/sitios/{id}/devolver        {estatus_destino, motivo, comentario}     (If-Match)
POST /admin/sitios/{id}/descartar       {motivo, comentario}                      (If-Match)
POST /admin/sitios/{id}/reasignar       {coordinador_oid}                         (If-Match)
```

Rules enforced by `modules/transiciones/rules.py` (the PWA mirrors them only for hints):

| Transition | Requirement |
|---|---|
| → `dueno_localizado` | contact with non-blank name and phone |
| → `primera_visita` | visit with `frente_m > 0` and `fondo_m > 0` |
| → `recepcion_documentos` | every active required document type has a `vigente`, `publicado` file |
| → `descartado` by a coordinator | `comentario` required; marks the site `en_revision_admin` with a proposal, status unchanged |
| devolver | destination strictly earlier than the current status; active reason; comment 5 to 1000 characters; notifies the coordinator |
| descartar (admin) | any non-terminal site |
| reasignar | a different `coordinador_oid`; child rows follow; the previous phone drops the site in its next delta |

Skipping a stage returns 422 with `estatus_actual` and `estatus_siguiente`. Contact and visit
writes need no `If-Match` (only the owning coordinator writes them) but they bump the ETag.

## 7. Delta sync (PWA)

```text
GET /sitios/delta?desde=<rowversion hex>&conocidos=1,2,3
-> { items: [SitioDetail…], removed_ids: [..], max_rowversion: "<hex>" }
```

- `desde` omitted: full download. Otherwise every site whose `rowversion` is above the watermark.
- `conocidos` is the list of ids the phone holds; any that the caller can no longer see
  (reassigned, no longer `vigente`) come back in `removed_ids`. The client chunks long lists under
  the SQL Server parameter cap (audit B-03).
- Store `max_rowversion` as the next `desde`.

## 8. Resumable upload protocol

```text
POST /subidas                 {sitio_id, tipo: "documento"|"foto", tipo_documento?, nombre_original,
                               content_type, bytes_total, sha256}
                              -> 201 SubidaOut {id, tamano_parte, partes_total, expira_utc, …}
PUT  /subidas/{id}/partes/{n} raw bytes, n from 0; every part exactly tamano_parte except the last
                              -> PartesOut {partes_recibidas}
POST /subidas/{id}/completar  -> 200 ArchivoMeta (published)  |  202 {estado: "escaneando"}
GET  /subidas/{id}            -> SubidaOut (partes_recibidas while abierta)   to resume after a cut
DELETE /subidas/{id}          -> 204 (not allowed once publicada)
```

Limits and checks: PDFs up to 150 MiB and 50 pages, not encrypted, real type by signature;
photos JPEG/PNG/WebP up to 1.5 MiB; parts of 4 MiB; sessions expire after 72 h. On `completar`
the service verifies size and SHA-256, then asks the scanner: `SCAN_MODE=none` publishes at once,
`defender` reads the blob tag and returns 202 until the result exists; the `promote` job finishes
the publication. A replaced document keeps earlier versions (`version`, `vigente`).

Download: `GET /archivos/{id}` (audited before streaming, `Cache-Control: private, no-store`),
`HEAD /archivos/{id}` for the same headers without a body or an audit row,
`GET /archivos/{id}/meta` for metadata.

## 9. Bulk load

```text
POST /admin/cargas            multipart file (csv, xlsx, xls; first sheet; ≤ 10 MB, ≤ 5000 rows)
                              -> 201 LoteSummary (estado vista_previa)
GET  /admin/cargas/{id}       -> LoteDetail {lote, filas: {items, next_cursor}}
POST /admin/cargas/{id}/decisiones  [{num_fila, decision: "aprobar"|"excluir"}]  (warning rows only)
POST /admin/cargas/{id}/confirmar   -> ConfirmResult {insertadas, actualizadas, revision}
POST /admin/cargas/{id}/cancelar    -> LoteSummary
```

Required columns (accents and case ignored): `#`, `USUARIO`, `REGIÓN`, `SITIO`, `COORDENADAS`,
`GPS`, `POTENCIAL`, `CAMPOS`, `FECHA`. Row validation codes and their messages are in
`modules/cargas/validation.py`; `docs/SUPPORT_GUIDE.md` lists them with the fix for each.
Confirm runs in one transaction, inserts new `#` as `sitio_prospectado`, updates file fields of
existing ones and never touches status, captures, files or the coordinator of a site that has
already advanced (those rows go to admin review).

## 10. Other endpoints

| Endpoint | Notes |
|---|---|
| `GET /me` | `{oid, name, username, roles}` of the token |
| `GET /catalogos` | `estatus`, `motivos_devolucion`, `tipos_documento` (the UI labels come from here) |
| `GET /sitios/resumen` | `{estatus: count}` for `vigente` sites visible to the caller |
| `GET /notificaciones`, `POST /notificaciones/{id}/leer` | Coordinator only; latest 100; read is idempotent |
| `GET /admin/equivalencias`, `PUT /admin/equivalencias`, `PUT /admin/equivalencias/{codigo}` | The bulk `PUT` is all-or-nothing: one unresolved email rejects the whole batch with `errors[]` per code |
| `GET /admin/auditoria` | Filters `usuario_oid`, `entidad`, `entidad_id`, `accion`, `desde`, `hasta` |
| `GET /healthz`, `GET /readyz` | Liveness; readiness with database and both storage containers |

## 11. Audit actions you will see in the ledger

`contacto_capturado`, `visita_capturada`, `transicion`, `descarte_propuesto`, `devolucion`,
`descarte`, `reasignacion`, `carga_creada`, `carga_decision`, `carga_confirmada`,
`carga_cancelada`, `equivalencia_actualizada`, `subida_iniciada`, `subida_cancelada`,
`archivo_publicado`, `archivo_retirado`, `archivo_descargado`, `archivo_rechazado_malware`,
`archivo_purgado`. Every row carries the caller's `oid`, role, client IP (respecting
`TRUSTED_PROXY_HOPS`) and the correlation id of the request.
