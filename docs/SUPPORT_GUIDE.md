# Support guide · Pipeline de Posibles Tiendas

Date: 11 October 2026 · Branch `ux-redesign` · **Audience:** L1 (TI service desk) and L2
(Subdirección de Inteligencia Artificial) · **When to read:** a coordinator or the administrator
reports a problem · **Source of truth:** `docs/OPERATIONS.md` for platform runbooks, the code for
behaviour; this guide starts from the user's symptom.

> **Before any "sign out and back in" advice:** "Salir" in the coordinator app deletes everything
> stored on the phone, including captures and photos not yet sent. When something is unsent the
> app asks first ("¿Salir sin enviar?", with "Sincronizar primero" and "Salir y borrar"); tell the
> coordinator to choose "Sincronizar primero" and wait for the chip to read "Al día". Blocked items
> ("n requieren atención") never sync on their own: they must be resolved from the site first.
> Only "Al día" is safe to sign out from.

## 1. Who does what

| Tier | Who | Handles | Escalates when |
|---|---|---|---|
| L1 | TI service desk | Access problems, device and signal questions, "where do I find…", this guide's symptom tables | The fix needs data access, a job run, a code change, or the symptom is not listed |
| L2 | Subdirección de IA (product and engineering) | Data corrections through the admin web, job reruns, log and audit queries, defects | Azure platform incidents (TI infra), identity (Identidad), security events (Seguridad) |

Severity and response targets are a pending decision (`IMPROVEMENT_BACKLOG.md` SUPPORT); until
then use the incident model in `architecture/PRODUCTION_READINESS.md` §7 as the default.

## 2. How to trace any error

1. Ask for the **reference** shown under the error ("Referencia: `f598…`"). It is the request's
   correlation id, generated by the server.
2. Find the write it belonged to: `SELECT * FROM auditoria WHERE correlation_id = '<id>'`
   (`docs/DATA_MODEL.md` §5). Reads that failed before writing leave no audit row.
3. Find the log line: locally `make logs | grep <id>`; in Azure, KQL on
   `ContainerAppConsoleLogs_CL` filtering `correlation_id`. The line carries `route`, `status`
   and a hashed user id, never personal data.
4. Match the status to the error table in `docs/API_GUIDE.md` §4 to know what rule fired.

## 3. Coordinator app (phone)

| Symptom | Likely cause | What to check | Fix |
|---|---|---|---|
| "No tienes sitios asignados" | No equivalence for the coordinator's code, or no load assigned sites to them | Admin web → Equivalencias: is the code active and "Cuenta resuelta"? Sitios filtered by coordinator | Fix the equivalence email and save (it re-resolves); or load the file |
| Sites missing that were there yesterday | Reassigned by the admin, or marked no vigente by a load | Admin web → site → Historial (`Reasignación`) | Expected; the previous phone drops them at the next sync |
| Chip shows "n por enviar" for a long time | No signal, server unreachable, or session expired | Banner under the top bar: "Sin señal" / "El servidor no responde" / "Tu sesión expiró" | Get signal; sign in again when asked (the queue is kept); do **not** sign out |
| "n requieren atención" / red card "Cambios que no se pudieron aplicar" | The server rejected a queued change: 412 (admin changed the site meanwhile), 422 (requirements missing), 404 (site no longer theirs) | The panel shows the server message and the server's current status | Coordinator chooses "Reintentar con el estado actual" (re-applies on top of the server state) or "Descartar cambio local". A 412 after an admin return is normal |
| "Avanzar" is disabled | Checklist in "Siguiente paso" has pending items | The checklist links to the section to complete | Complete contact / measurements / the four PDFs |
| Sync error "No se pudo sincronizar tras varios intentos" | Five transient failures (5xx, 429) | API health (`/readyz`), Azure revision status | Fix the platform; the coordinator presses "Reintentar" |
| PDF upload fails | No signal (PDFs are online only); file not a PDF; encrypted; over 150 MB or 50 pages; wrong document type | The message under the document row | Get a clean PDF; the upload resumes where it stopped |
| Document stays "Recibido. Se publicará cuando termine la revisión antimalware" | Defender scan result pending or the `promote` job not running | `docs/OPERATIONS.md` RB-02; `subida_sesion` rows in `escaneando` | Run `promote`; if the result never arrives the session expires after 72 h and the file must be re-uploaded |
| Photo rejected "demasiado grande" | Could not compress under 1.5 MB after six attempts | Original image size | Take the photo again at a lower resolution |
| Wrong site state shown (stale) | Local cache diverged (rare; after a database restore or reset) | Compare with the admin web | Sync first, then "Salir" and sign in again to re-download (backlog UX-P12 will add a safer action) |
| "La cuenta … no tiene el rol Coordinador" | User not in `PIPELINE-Coordinadores` (prod) or picked the wrong dev user | Entra group membership | Identidad adds the user; sign in again |
| Cannot sign in at all (Entra) | Conditional Access, device not compliant, token lifetime | Entra sign-in logs | Identidad / Intune |
| Avisos empty although the admin returned a site | Outbox failing or notification read elsewhere | `notificacion_outbox` state; RB-03 | The site still shows "Devuelto" in Mis sitios with the reason; fix the outbox |

Reassurance script: captures are stored on the phone until the server confirms them; a phone
without signal loses nothing as long as the user does not sign out.

## 4. Admin web

| Symptom | Likely cause | What to check | Fix |
|---|---|---|---|
| Load rejected before preview | Missing column, unsupported type (`.xlsm`), empty file, over 10 MB or 5,000 rows | The Problem Details message lists `missing` columns | Fix the file; column names ignore accents and case |
| Rows in error | See the code table below | "Motivos" column (message plus code) | Errors are never loaded; fix the file and re-upload, or add the equivalence |
| "Confirmar carga" disabled | Warnings without a decision | The sentence under the action bar says how many | Decide each warning (or "Aprobar todas" / "Excluir todas"); confirm saves them |
| Confirm returns 409 | Load already confirmed or cancelled (double click, two tabs) | Cargas list state | Nothing to do |
| Site "en revisión del administrador" | A load assigned an advanced site to another coordinator, or the coordinator proposed a discard | Site detail alert with the detail text | Reasignar, Devolver or Descartar |
| "El registro cambió desde que lo abriste" | 412: the coordinator synced a change meanwhile | Reload the site | Repeat the action |
| "Devolver" disabled | Site in the first stage or terminal | Text under the stage bar explains | Expected |
| Equivalence save fails with marked rows | Email not found in the directory | The row shows the message; nothing was saved | Correct the email; all rows save together |
| Coordinator shows "sin resolver" | Account not yet in Entra, or typo | Equivalencias page warning | Save again after the account exists (saving re-resolves) |
| Audit log empty for a user | Filter by the wrong account | "Otra cuenta (oid)" option accepts any oid | — |

### Load validation codes

| Code | Level | Meaning | What the admin does |
|---|---|---|---|
| `id_vacio`, `id_no_numerico` | error | `#` empty or not a positive integer | Fix the file |
| `id_repetido` | error | Same `#` twice in the file | Remove the duplicate |
| `usuario_vacio` | error | `USUARIO` empty | Fix the file |
| `usuario_sin_equivalencia` | error | Code has no active, resolved equivalence | Add or fix the equivalence, then re-upload |
| `region_vacia`, `sitio_vacio` | error | Empty region or site name | Fix the file |
| `coordenadas_formato` | error | Not `lat, lon` | Fix the file |
| `coordenadas_fuera_rango` | error | Outside Mexico | Fix the file |
| `potencial_invalido` | error | Not one of Muy alto, Alto, Medio, Bajo, Sin estatus | Fix the file |
| `campos_formato` | error | `CAMPOS` not `n/m` | Fix the file |
| `fecha_formato` | error | Date not ISO 8601 or `mm/dd/yyyy hh:mm` | Fix the file |
| `nombre_sospechoso` | warning | Name contains prueba, viable, equivocado, ubicación, test | Approve if real, exclude if a placeholder |
| `coordenadas_cercanas` | warning | Within 15 m of another row or site | Check for a duplicate; approve or exclude |
| `campos_incompletos` | warning | Fewer fields than total | Usually approve |
| `usuario_cambiado` | warning | Different coordinator than before (site still in stage 1) | Approve to reassign, exclude to keep |
| `usuario_cambiado_sitio_avanzado` | warning | Different coordinator on a site that already advanced | Approving sends it to admin review, not a reassignment |
| `datos_cambiados` | warning | Region or name changed vs the stored site | Approve to update |

## 6. Data corrections

All corrections go through the admin web (Devolver, Reasignar, Descartar, Equivalencias, loads),
which keeps the audit ledger complete. Direct SQL updates are a last resort by L2 with a ticket,
never on the ledger tables (the database denies it) and never on `sitio` without recording why in
the ticket; a manual `UPDATE` bumps the `rowversion`, so coordinators with queued changes on that
site will see a conflict, which is the intended behaviour.

## 7. Frequently asked questions

- **Can two coordinators share a phone?** Not safely: "Salir" wipes local data and the question is
  pending with the business (TO_BE Q6).
- **How long does a coordinator stay signed in offline?** Entra refresh tokens for SPAs last 24 h;
  after that the app asks to sign in and keeps the queue. Not yet measured on a real device.
- **Where are the PDFs?** Blob storage `pipeline/{sitio_id}/{tipo}/…` in the documents account;
  downloads only through the API, every download is audited.
- **How long are documents kept?** Five years from upload (`purga_utc`), then the blob is deleted
  and the metadata kept. The business event that starts retention is still pending (Legal).
- **Can a load undo a coordinator's work?** No. Confirming a load never touches status, captures,
  files or the coordinator of a site that has advanced.
